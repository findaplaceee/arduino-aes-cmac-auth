# Аутентификация сообщений на базе Arduino


## Описание проекта

Данный проект является практической реализацией механизма аутентификации сообщений с использованием MAC. Основная задача проекта — показать, как принимающая сторона может проверить, что переданное сообщение не было изменено в процессе передачи и было сформировано доверенным отправителем.

В проекте представлены две реализации:

* `arduino+PC` — вариант, где персональный компьютер формирует сообщение и MAC, а Arduino принимает пакет и проверяет его;
* `solo_arduino` — вариант, где обмен выполняется между Arduino без использования Python-отправителя на ПК.

Обе реализации демонстрируют один и тот же принцип: сообщение передаётся вместе с MAC-тегом, после чего принимающая сторона повторно вычисляет MAC и сравнивает его с полученным значением.

## Папка arduino+PC

Папка `arduino+PC` содержит вариант реализации, в котором персональный компьютер используется как отправитель сообщения.

В этом варианте программа на ПК формирует текстовое сообщение, вычисляет для него MAC и отправляет пакет на Arduino через последовательный порт. Arduino принимает данные, выделяет сообщение и MAC-тег, затем повторно вычисляет MAC и сравнивает результат.

Общая схема работы:

```text
ПК → USB/UART → Arduino
```

Порядок работы:

1. Подключить Arduino к компьютеру через USB.
2. Открыть прошивку Arduino из папки `arduino+PC`.
3. Загрузить прошивку на плату через Arduino IDE.
4. Закрыть Serial Monitor в Arduino IDE.
5. Запустить программу на ПК.
6. Ввести сообщение.
7. Дождаться ответа от Arduino.

Если сообщение и MAC совпадают, Arduino выводит:

```text
MAC OK
```

Если сообщение, MAC или ключ были изменены, Arduino выводит:

```text
MAC ERROR
```

Важно: Serial Monitor в Arduino IDE должен быть закрыт перед запуском программы на ПК, потому что один COM-порт не может одновременно использоваться двумя программами.

## Папка solo_arduino

Папка `solo_arduino` содержит вариант реализации без отдельной Python-программы на ПК.

В этом варианте логика обмена выполняется на стороне Arduino. Такой подход удобен для демонстрации работы механизма аутентификации в более автономном виде, когда основной обмен происходит между микроконтроллерными устройствами.

Общая схема работы:

```text
Arduino-отправитель → UART → Arduino-получатель
```

или, если используется одна плата для демонстрации логики:

```text
Arduino → формирование сообщения → проверка MAC
```

Порядок работы:

1. Открыть проект из папки `solo_arduino`.
2. Загрузить прошивку на Arduino.
3. Подключить платы между собой, если используется вариант с двумя Arduino.
4. Убедиться, что между платами соединён общий GND.
5. Запустить обмен сообщениями.
6. Проверить результат в Serial Monitor.

При корректной передаче принимающая сторона должна вывести сообщение об успешной проверке MAC. При изменении данных проверка должна завершиться ошибкой.

## Формат передаваемого пакета

В базовой реализации используется текстовый формат пакета:

```text
message|MAC_HEX
```

Где:

* `message` — передаваемое сообщение;
* `|` — разделитель;
* `MAC_HEX` — MAC-тег в шестнадцатеричном виде.

Пример пакета:

```text
hello|5F2A0C4B8E1D7A9C3B6F0123456789AB
```

Arduino принимает строку, отделяет сообщение от MAC, вычисляет MAC повторно и сравнивает два значения.

## Используемые технологии

В проекте используются:

* Arduino;
* Arduino IDE;
* последовательный интерфейс UART;
* Python для варианта `arduino+PC`;
* механизм MAC для проверки целостности и подлинности сообщения.

## Назначение проекта

Проект показывает полный цикл проверки сообщения:

1. Формирование исходного сообщения.
2. Вычисление MAC.
3. Передача сообщения и MAC.
4. Приём пакета.
5. Повторное вычисление MAC.
6. Сравнение полученного и вычисленного значения.
7. Принятие или отклонение сообщения.

Если значения MAC совпадают, сообщение считается корректным. Если значения отличаются, сообщение отклоняется.

## Проверяемые ситуации

В ходе работы можно проверить следующие случаи:

| Ситуация                                   | Ожидаемый результат                      |
| ------------------------------------------ | ---------------------------------------- |
| Передано корректное сообщение              | MAC OK                                   |
| Изменён один символ сообщения              | MAC ERROR                                |
| Изменён один символ MAC                    | MAC ERROR                                |
| Используется другой ключ                   | MAC ERROR                                |
| Нарушен формат пакета                      | Ошибка формата                           |
| Повторно отправлен тот же корректный пакет | В базовой версии пакет может быть принят |

## Ограничения учебной реализации

Данный проект является учебным прототипом. В нём могут использоваться заранее заданные ключи, записанные прямо в исходном коде. Такой вариант подходит для демонстрации, но не должен использоваться в реальных системах защиты.

Для практического применения необходимо:

* не хранить секретный ключ открыто в коде;
* добавить защищённое хранение ключей;
* использовать счётчик сообщений или nonce;
* включать служебные поля в данные, по которым вычисляется MAC;
* защищаться от повторной передачи старых пакетов;
* использовать более строгий бинарный формат пакета.

## Защита от повторной передачи

Базовая проверка MAC позволяет обнаружить изменение сообщения, но сама по себе не защищает от replay-атаки. Если злоумышленник перехватит корректный пакет и отправит его повторно, MAC может снова пройти проверку.

Для защиты от такой атаки в пакет можно добавить счётчик:

```text
counter|message|MAC_HEX
```

В этом случае MAC должен вычисляться не только от сообщения, но и от счётчика. Получатель хранит последний принятый номер пакета и отклоняет старые или повторные сообщения.

## Итог

Проект демонстрирует работу механизма аутентификации сообщений на базе Arduino. Реализация показывает, что принимающая сторона может самостоятельно проверить целостность сообщения и обнаружить его изменение без необходимости доверять входящим данным заранее.

Папка `arduino+PC` предназначена для варианта с компьютером и Arduino, а папка `solo_arduino` — для автономной реализации на Arduino. Обе части относятся к одному проекту и поэтому размещены в одном репозитории.
