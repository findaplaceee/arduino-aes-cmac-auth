# arduino-aes-cmac-auth
Проект: Аутентификация сообщений с использованием AES-CMAC на базе Arduino

Автор: Руденко Иван Евгеньевич

Описание проекта

Данный проект является практической частью выпускной квалификационной работы по теме аутентификации текста MAC и аутентификации источника на базе микроконтроллера.

Цель проекта — показать, как можно проверить целостность и подлинность передаваемого сообщения с помощью механизма AES-CMAC. В работе рассматривается ситуация, когда сообщение передаётся по каналу связи, а принимающая сторона должна определить, было ли оно изменено или подменено.

В проекте представлены две реализации:

1. pc_arduino — вариант, где персональный компьютер выступает отправителем, а Arduino Mega 2560 принимает сообщение и проверяет MAC.

2. arduino_2 — вариант обмена между двумя Arduino, где одна плата формирует сообщение и MAC, а вторая принимает пакет и выполняет проверку.

Структура проекта

pc_arduino/

Папка содержит реализацию варианта «ПК — Arduino».

В этом варианте Python-программа на компьютере принимает текстовое сообщение, вычисляет AES-CMAC и отправляет пакет на Arduino через COM-порт. Arduino принимает строку, выделяет сообщение и MAC-тег, повторно вычисляет AES-CMAC и сравнивает результат с полученным значением.

Состав:

* python_sender/sender.py — программа отправителя на Python;
* arduino_receiver/arduino_receiver.ino — прошивка для Arduino Mega 2560.

arduino_2/

Папка содержит реализацию варианта обмена между двумя платами Arduino.

В этом варианте одна Arduino выполняет роль отправителя, формирует сообщение и передаёт его принимающей плате. Вторая Arduino принимает пакет, вычисляет MAC и выводит результат проверки.

Состав:

* sender_arduino/sender_arduino.ino — прошивка для Arduino-отправителя;
* receiver_arduino/receiver_arduino.ino — прошивка для Arduino-получателя.

Используемые технологии

* Arduino Mega 2560;
* Arduino IDE;
* Python;
* последовательный интерфейс UART;
* AES-CMAC;
* формат передачи message|MAC_HEX.

Принцип работы

В базовом варианте пакет имеет следующий формат:

message|MAC_HEX

Первая часть содержит передаваемое сообщение. После разделителя | передаётся MAC-тег в шестнадцатеричном виде.

Пример:

hello|5F2A0C4B8E1D7A9C3B6F0123456789AB

Arduino принимает пакет, отделяет сообщение от MAC, вычисляет AES-CMAC от принятого сообщения и сравнивает вычисленное значение с переданным тегом.

Если значения совпадают, выводится результат:

MAC OK

Если сообщение, MAC или ключ были изменены, выводится:

MAC ERROR

Запуск варианта PC — Arduino

1. Подключить Arduino Mega 2560 к компьютеру через USB.
2. Открыть Arduino IDE.
3. Выбрать плату Arduino Mega or Mega 2560.
4. Выбрать процессор ATmega2560.
5. Указать нужный COM-порт.
6. Загрузить прошивку из папки pc_arduino/arduino_receiver.
7. Закрыть Serial Monitor в Arduino IDE.
8. Открыть Python-скрипт из папки pc_arduino/python_sender.
9. Указать в коде нужный COM-порт.
10. Запустить Python-программу.
11. Ввести сообщение и проверить ответ Arduino.

Важно: Serial Monitor должен быть закрыт, потому что один COM-порт не может одновременно использоваться Arduino IDE и Python-программой.

Запуск варианта Arduino 2

1. Подключить первую Arduino к компьютеру.
2. Загрузить на неё прошивку sender_arduino.ino.
3. Подключить вторую Arduino.
4. Загрузить на неё прошивку receiver_arduino.ino.
5. Соединить платы через UART.
6. Подключить общий GND между двумя платами.
7. Запустить обмен и проверить вывод результата.

Назначение проекта

Проект показывает полный цикл аутентификации сообщения:

* формирование сообщения;
* вычисление MAC;
* передача пакета;
* приём пакета;
* повторное вычисление MAC;
* сравнение значений;
* принятие или отклонение сообщения.

Практический смысл реализации заключается в том, что получатель не доверяет входящим данным сразу. Он принимает сообщение только после успешной проверки MAC.

Ограничения учебной реализации

В проекте используется демонстрационный ключ, записанный прямо в исходном коде. Такой способ удобен для учебного прототипа, но не подходит для реального применения.

В реальной системе секретный ключ нельзя хранить открыто в коде. Его необходимо защищать с помощью специальных механизмов хранения, ограничения доступа к памяти и отключения отладочных интерфейсов.

Также базовая версия проекта проверяет целостность сообщения, но сама по себе не защищает от повторной передачи ранее перехваченного корректного пакета. Для защиты от replay-атаки необходимо добавить счётчик сообщений, nonce или временную метку и включать это поле в данные, по которым вычисляется MAC.

Итог

Разработанный проект демонстрирует, что механизм AES-CMAC может использоваться для проверки целостности и подлинности сообщений в микроконтроллерных системах. Реализация подходит для учебного прототипа и может быть расширена за счёт добавления счётчика пакетов, бинарного формата передачи и более безопасного хранения ключей.
